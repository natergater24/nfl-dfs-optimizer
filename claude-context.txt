NFL DFS LINEUP OPTIMIZER - PROJECT BRIEFING (2026-10-12)

PURPOSE
Personal-use engine that builds DraftKings NFL Sunday main-slate lineups for every DK
contest type (Head-to-Head, 50/50, Double Up, Multiplier 3x/5x/10x, Single Entry / 3-Max,
Tournament, Large-Field Tournament). Never logs in to DraftKings or enters contests.
Spec: docs/superpowers/specs/2026-10-11-nfl-dfs-optimizer-design.md
Plan 1 (engine, this build): docs/superpowers/plans/2026-10-12-nfl-dfs-engine.md
Branch: engine. Run via ./py (system Python 3.14). Tests: ./py -m pytest -q (109 pass, also clean under -W error).

DATA SOURCES
- DK lobby JSON (unauthenticated): https://www.draftkings.com/lobby/getcontests?sport=NFL
- DK salary CSV (official Export to CSV URL):
  https://www.draftkings.com/lineup/getavailableplayerscsv?contestTypeId={contest_type_id}&draftGroupId={draft_group_id}
- FINDING: DK's JSON "draftables" API returns 403 and must not be used; the CSV URL is the
  same file as the manual fallback (--salary-csv), so one parser serves both.
- nflverse via nflreadpy (player/team weekly stats). Vegas lines: The Odds API
  (ODDS_API_KEY in git-ignored env.txt; shared 500/month quota with MLB_Pipeline; ~2 units per run).

  1. Name match rate 83% (offense, playable). Unmatched are 2026 rookies/backups/$4,000 filler (Ty Simpson,

  3. Ownership: 2 players are pinned at the 60% ownership cap (Puka Nacua, Kyren Williams); before the fix wave
     it was 3 (Jaylen Warren, Kyren Williams, Tyler Higbee). Position totals match SLOT_TOTALS. Per-team usage
     share totals are held at the 0.97 cap. Accepted; ownership regression waits for real results.
  4. Cash lineups (H2H/50-50/Double Up) are identical and Chalk-heavy as intended; Large-Field Tournament is
     all-Contrarian with a stack; Single Entry / 3-Max has a QB stack. Pass.
- Task 6b diagnosis (compressed usage shares), three causes, all fixed: (a) shrinkage toward average-starter
  priors pulled depth players UP so team sums exceeded the cap and scaled starters down -> replacement-level
  priors, shrink by unweighted games, k=0.5; (b) a player's last 6 games on ANY team were credited to his
  current team -> shares measured per (player, team); (c) many small floor shares summed past the cap ->
  the cap trims low-evidence (<3 games) players first (never below 25% of their share) before scaling anyone.
- Final-wave fix (stale redistribution): redistribute() handed every non-playable player's share to teammates,
  including long-term IR players whose absence teammates' recent shares already reflect (ARI got 0.66 carry share
  from Conner/Benson; Herbert got Trey Lance's carries). compute_shares now emits team_games_since (that team's
  games after the player's last one); only players with team_games_since <= RECENT_ABSENCE_GAMES (1) are
  redistributed, stale ones are zeroed. Effect: Jeremiyah Love carry 0.426 -> 0.408,
  tgt 0.098 -> 0.055; Justin Herbert carry 0.253 -> 0.151, median 14.6 -> 13.2.
- Other final-wave fixes: Odds API errors no longer include the URL/apiKey (RuntimeError, from None);
  thursday/sunday re-run stats if player_weeks.parquet is older than the last Tuesday 00:00 (skip message states
  the data's season/week); a DK lobby block gives the same --salary-csv guidance as the CSV fetch.
- Accepted rulings: T5 team-model coefficients (pass_yds slope ~10/pt implied total) accepted; shrinkage by
  games; per-team share measurement; projections accepted as above; subagent commit trailers carry their own
  model name; first 8 commits keep the hostname author email (reset before first GitHub push).
